# Правила работы с репозиторием Heat Up

## 🎯 О проекте

Heat Up — сервис автоматического прогрева Telegram-аккаунтов через LLM-генерируемое поведение.

**Production:**
- Сервис: `python main.py` (FastAPI на порту 8080)
- База данных: `data/sessions.db` (SQLite)
- Логи: `logs/heat_up.log`

## 🔒 КРИТИЧНО: Изоляция аккаунтов (Anti-Linking)

**Цена ошибки: $15 за каждый замороженный аккаунт!**

Telegram связывает и замораживает аккаунты которые:
- Пишут в одни и те же чаты
- Делают действия одновременно
- Имеют похожие паттерны поведения
- **Вступают в одни каналы** (особенно системные типа @TGStat!)

### ⚠️ ЗАПРЕЩЁННЫЕ КАНАЛЫ (вызывают массовые заморозки!)
**НИКОГДА** не вступать в эти каналы — они связывают аккаунты:
- @TGStat, @TGStat_Chat, @TGStatAPI, @TGStat_Bot
- @SearcheeBot, @telepulse, @TGAlertsBot
- @share (популярный канал с пересечениями)

Эти каналы добавлены в blacklist в `search_agent.py`.

### Обязательные правила при разработке:

1. **Один warmup-аккаунт = один чат**
   - Проверять `is_chat_exclusive_for_warmup()` перед ЛЮБЫМ действием в чате
   - Если чат занят другим warmup → БЛОКИРОВАТЬ действие

2. **Никаких одновременных действий**
   - Аккаунты НЕ должны делать ничего в одно время
   - Использовать случайные задержки
   - Разносить активность по времени

3. **Каждый аккаунт = уникальная личность**
   - Разные персоны, интересы, стиль общения
   - Разные чаты и каналы
   - Разное время активности

4. **Лимиты на чат:**
   - Максимум 7 сообщений в чат за весь период прогрева
   - Максимум 3 сообщения в чат в день
   - После 7 сообщений → чат закрыт для аккаунта навсегда

### При добавлении новых features:

- [ ] Не создаёт паттерны связывания?
- [ ] Аккаунты выглядят как разные люди?
- [ ] Нет одновременных действий?

## 🧠 Система памяти персоны

Каждое отправленное сообщение сохраняется в `sent_messages`:
- `message_text` - полный текст
- `context_summary` - причина/контекст
- `sent_at` - время отправки

При генерации нового сообщения ChatContextAnalyzer получает:
1. **Предыдущие сообщения персоны** в этом чате (последние 10)
2. **Контекст чата** (последние 30 сообщений)

Это предотвращает:
- Повторение одних и тех же фраз
- Противоречие самому себе
- Неестественное поведение

## 🔌 API Справочник

### Admin API (`data/adminapi.json`)

Основной API для управления сессиями Telegram.

**Получение helper-аккаунтов (спамблок, для массовки):**
```bash
# HTTP запрос
curl "https://admin-api.example.com/api/v1/sessions/?spamblock=true&status=2"

# SQL эквивалент
SELECT * FROM session WHERE status = 2 AND spamblock AND unban_date IS NULL
```

Helper-аккаунты:
- **НЕ могут** инициировать DM (спамблок)
- **Могут** отвечать на DM
- **Могут** писать в группах
- Используются как "массовка" для общения между ботами
- Синхронизируются автоматически при запуске scheduler (`sync_helper_accounts()`)

**Статусы сессий в Admin API:**
- `status=0` — **ГОТОВ К РАБОТЕ** (свободен, можно прогревать)
- `status=1` — **В РАБОТЕ** (шлёт рассылки, НЕ трогать!)
- `status=2` — **БАН** (забанен, не использовать)
- `frozen=True` — заморожен Telegram, НЕ использовать
- `deleted=True` — удалён, НЕ использовать

**ВАЖНО:** Warmup аккаунты должны иметь `status=0`. Если status=1 — сессия занята рассылками. Status=2 — это БАН!

**ВАЖНО: Проверка status=1**
- Перед отправкой DM проверяется `check_session_status()` через Admin API
- Аккаунты с `status=1` **НЕЛЬЗЯ** добавлять как получателей DM
- Используется `get_session_by_id()` (НЕ search!) для корректной проверки

**Основные эндпоинты:**
- `GET /api/v1/sessions/` — список сессий с фильтрами
- `GET /api/v1/sessions/{id}/` — детали сессии
- Параметры: `spamblock`, `status`, `deleted`, `frozen`, `country`, `provider`

### Account Management API (`data/openapi.json`)

API для прямого управления аккаунтами и выполнения действий.

**Основные эндпоинты:**
- `/invoke` — выполнение Telegram RPC вызовов
- `/send_message` — отправка сообщений
- `/join_channel` — вступление в каналы
- `/get_dialogs` — получение диалогов
